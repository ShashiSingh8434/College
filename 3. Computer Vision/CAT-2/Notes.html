UNIT 01

Feature Extraction — Edges, Lines, Corners, Descriptors

⚠ EXAM HOT

Edge Detection — Canny, LoG, DoG

Definition An edge is a significant local change in image intensity. Edge detection finds boundaries between regions by locating pixels where intensity changes sharply.

1. Gradient Basics (needed for ALL edge methods)

Gx = ∂I/∂x    Gy = ∂I/∂y    |G| = √(Gx² + Gy²)    θ = arctan(Gy / Gx)
  • |G| (Magnitude) — tells HOW STRONG the edge is; higher value = stronger edge
  • θ (Orientation) — tells which DIRECTION the edge goes (horizontal, vertical, diagonal)

Canny Edge Detector Most Asked

Gaussian Blur — smooth image to remove noise: G(x,y) = (1/2πσ²) · e^(−(x²+y²)/2σ²)
Compute Gradient magnitude |G| and direction θ using Sobel operators
Non-Maximum Suppression (NMS) — keep only local maxima along gradient direction → thin edges
Double Thresholding — classify pixels as strong (>T_high), weak (T_low < p < T_high), or ignored
Edge Tracking by Hysteresis — keep weak pixels only if connected to strong pixels
Input Image │ ▼ [Gaussian Blur] ──── removes noise │ ▼ [Sobel Operator] ─── Gx, Gy → |G|, θ │ ▼ [Non-Max Suppression] ── thins edges │ ▼ [Double Threshold] ─── strong/weak/none │ ▼ [Hysteresis] ─────── final edge map
✅ Pros
  • Best noise robustness
  • Thin, precise edges
  • Two-threshold → fewer false edges
❌ Cons
  • Slow (5 steps)
  • Threshold tuning needed
  • Misses blurry edges

LoG (Laplacian of Gaussian)

LoG(x,y) = −(1/πσ⁴)[1 − (x²+y²)/2σ²] · e^(−(x²+y²)/2σ²)
Smooth image with Gaussian filter (removes noise)
Apply Laplacian (2nd derivative) to find zero-crossings
Zero-crossings = edge locations
✅ Pros
  • Good noise handling
  • Scale-controlled by σ
❌ Cons
  • Sensitive to noise at crossings
  • Slow — 2nd derivative computation

DoG (Difference of Gaussians) — SIFT uses this!

DoG(x,y,σ) = G(x,y,kσ) − G(x,y,σ)
  • Approximates LoG — much faster to compute
  • Subtracts two blurred images at different scales
  • Used in SIFT keypoint detection across scale space

Comparison Table

⚠ Exam Answer Tip (Q1 from Mock)Lane detection: |G| finds WHERE the edge is (high gradient = lane line), θ gives DIRECTION of the lane (0°=horizontal, 90°=vertical). Canny recommended for autonomous vehicles due to noise robustness.
Line Detector

Hough Transform — Line & Circle Detection

Definition Maps edge points from image space to a parameter (Hough) space. Points lying on the same line produce peaks in Hough space.

Algorithm

ρ = x·cos(θ) + y·sin(θ)    [Normal form of a line]
Apply edge detector (Canny) to get edge map
For each edge pixel (x,y), vote for ALL possible (ρ,θ) pairs
Accumulate votes in 2D Hough accumulator array H[ρ][θ]
Find peaks in H — each peak = a line in image
Back-project peaks to image space to draw detected lines
Image Space Hough Space (ρ,θ) y ρ │ * * * * │ ╱ (peak = line) │ * * │ ╱ │ * │ ╱_________________ θ └────────── x Each point → sine curve Intersection = common line

Circle Hough Transform

(x−a)² + (y−b)² = r²   →   Vote in 3D space (a,b,r)
✅ Pros
  • Robust to noise & missing points
  • Detects multiple lines simultaneously
  • Works with partial/occluded lines
❌ Cons
  • High memory for 2D/3D accumulator
  • Slow for large images
  • Only detects predefined shapes
⚠ Exam UseRobot warehouse shelf detection: Canny → Hough for straight lines → Harris for shelf corners. This 3-stage pipeline is frequently tested!

Corner Detection — Harris & Hessian-Affine

Definition Corners are points where intensity changes significantly in ALL directions. They are more stable and distinctive than edges for matching.

Harris Corner Detector

M = Σ w(x,y) · [Ix²   IxIy; IxIy   Iy²]    R = det(M) − k·trace(M)²
  • M = Structure tensor (2×2 matrix of gradients)
  • λ₁, λ₂ = eigenvalues of M
  • If both large → Corner (R > threshold)
  • If one large → Edge
  • If both small → Flat region (R ≈ 0)
  • k = 0.04 to 0.06 (empirical constant)
λ₂ │ Corner │ Edge │ ──────────┼──────────── λ₁ │ Edge │ Flat │

Hessian-Affine Detector

H(x,y) = [Ixx   Ixy; Ixy   Iyy]    det(H) = Ixx·Iyy − Ixy²
  • Uses 2nd-order derivatives (curvature information)
  • Detects BLOB-like regions, not just corners
  • Affine invariant — handles viewpoint changes
  • More stable than Harris under scale/rotation

⚠ MOST IMPORTANT

SIFT — Scale Invariant Feature Transform

Definition SIFT detects and describes local features that are invariant to scale, rotation, and partially to illumination and viewpoint changes.

4 Stages of SIFT

Scale-Space Extrema Detection: Build DoG pyramid at multiple octaves. Find local minima/maxima in 3D (x,y,scale) — these are keypoint candidates.
Keypoint Localization & Filtering: Use Taylor expansion to refine position. REJECT if: (a) |DoG| < 0.03 (low contrast), (b) Hessian ratio (r+1)²/r > threshold — eliminates edge responses (r=10 used by Lowe).
Orientation Assignment: Create histogram of gradient orientations (36 bins, 360°) in a region around keypoint. Dominant orientation = keypoint's orientation. This gives ROTATION INVARIANCE.
Keypoint Descriptor: 4×4 grid of cells, each with 8-bin orientation histogram = 4×4×8 = 128-D vector. Normalized to reduce illumination effects.
Original Image │ ├──[σ]──[kσ]──[k²σ]── ... (Gaussian Scale Space) │ ▼ DoG Pyramid (subtract adjacent scales) │ ▼ Find Extrema (compare to 26 neighbors in 3D) │ ▼ Reject low-contrast & edge pts (Hessian filter) │ ▼ Assign Orientation → 128-D Descriptor
🔢 Numerical: How Hessian Filters Edge Keypoints

Hessian at a keypoint: H = [[Dxx, Dxy],[Dxy, Dyy]]

Tr(H) = Dxx + Dyy    Det(H) = Dxx·Dyy − Dxy²

Ratio test: Tr(H)²/Det(H) < (r+1)²/r where r=10

If ratio is HIGH → one eigenvalue much bigger → it's an EDGE → REJECT

✅ Pros
  • Scale & rotation invariant
  • Robust to illumination
  • 128-D descriptor is very distinctive
❌ Cons
  • Slow — not real-time
  • 128-D vector = large memory
  • Poor with motion blur
Faster SIFT

SURF — Speeded-Up Robust Features

Definition SURF is a faster approximation of SIFT using integral images and box filters (Haar wavelets) instead of Gaussian convolutions.

Key Ideas

  • Detection: Fast Hessian using Box filters on integral images (approx. DoG)
  • Descriptor: 64-D vector (4×4 grid, 4 Haar wavelet responses each) → 2× faster than SIFT
  • Orientation: Dominant Haar wavelet response in 60° sliding window
  • U-SURF: Upright SURF — skip orientation step if rotation invariance not needed (even faster)

Object Detection

HOG — Histogram of Oriented Gradients

Definition HOG describes local shape/appearance by the distribution of intensity gradient orientations. Classic pedestrian/object detector.

Algorithm Steps

Divide image into cells (e.g., 8×8 pixels)
Compute gradient magnitude & direction for each pixel
Build 9-bin orientation histogram (0°–180°) per cell
Group cells into blocks (e.g., 2×2 cells), normalize the block histogram (L2 norm)
Concatenate all block histograms → final HOG feature vector
Feed to SVM classifier for detection
Image Window (64×128 for pedestrian) │ ▼ Compute Gx, Gy → |G|, θ for each pixel │ ▼ Each 8×8 cell → 9-bin orientation histogram │ ▼ 2×2 cells = 1 block → normalize (contrast invariance) │ ▼ Concatenate all block vectors → HOG descriptor │ ▼ SVM → Detect / Not Detect
✅ Pros
  • Excellent for pedestrian detection
  • Illumination invariant (block norm)
  • Simple + effective
❌ Cons
  • NOT scale or rotation invariant
  • Fixed image window size
  • Fails with occlusion

UNIT 02

Image Segmentation — Region, Edge, Graph, Texture

⚠ EXAM HOT

Region Growing Segmentation

Definition Start from seed pixels and iteratively add neighboring pixels that satisfy a similarity criterion (intensity, color, texture). Grows regions outward from seeds.

Algorithm

Seed Selection: Choose initial seed pixel(s) inside the target region (manually or automatically)
Initialize: Add seeds to region R, add to queue
Grow: For each pixel in queue, examine neighbors (4-connected or 8-connected)
Similarity Test: If |I(neighbor) − I(seed)| < threshold T → add to region R
Repeat: Until no more pixels can be added (queue empty)
Seed (S) │ ▼ [S]──check N,E,S,W neighbors │ ├─ |I(nbr) - I(seed)| ≤ T? ──YES──► Add to Region R │ Add to Queue └─ NO → Skip Repeat until Queue empty

Key Parameters

  • Seed Selection: Critical — wrong seeds → wrong regions. Use domain knowledge (thermal defect: user clicks)
  • Similarity Threshold T: Low T → under-segmentation (too small); High T → over-segmentation/leakage
  • Connectivity: 4-connected (up/down/left/right) or 8-connected (includes diagonals)
✅ Pros
  • Simple and intuitive
  • User can guide via seeds
  • Good for known defect regions
❌ Cons
  • Leakage across weak boundaries
  • Sensitive to noise and threshold
  • Requires good seed selection
⚠ Exam TipFor thermal defect/agricultural leaf/satellite flood questions: always mention seed selection → grow with threshold → use 8-connectivity → apply Graph-Cut to refine. This hybrid = standard exam answer!
Edge-Based

Edge-Based Segmentation — Active Contours / Level Sets

Definition Uses detected edges/boundaries to delineate regions. Active contours (snakes) deform toward strong edges under energy minimization.

Active Contours (Snakes)

E_total = E_internal + E_external = ∫(α|v'|² + β|v''|²) ds − γ|∇I|²
  • E_internal: Controls smoothness (α=elasticity, β=stiffness)
  • E_external: Pulls contour toward image edges (gradient magnitude)
  • Contour iteratively deforms to minimize total energy
Initialize contour around target (user draws rough outline)
Compute gradient-based edge force at each contour point
Update contour positions to reduce E_total
Iterate until convergence (contour stops moving)

Level Set Method (advanced)

  • Represents contour as implicit zero-level of a 3D function φ(x,y)
  • Handles topology changes (merging, splitting) automatically
  • Better for complex shapes (CT/MRI vessel segmentation)
✅ Pros
  • Handles smooth boundaries
  • Level sets handle topology changes
  • Works on CT/MRI/ultrasound
❌ Cons
  • Leaks through weak/faint edges
  • Computationally intensive
  • Sensitive to initialization
⚠ KEY TOPIC

Graph-Cut Segmentation

Definition Models image as a graph. Each pixel = node. Edges carry weights based on similarity. Min-cut algorithm partitions graph into foreground (Source) and background (Sink).

Graph Structure

  • Nodes: Each pixel + Source (S) + Sink (T)
  • n-links (neighborhood): Edges between adjacent pixels, weight = similarity (high weight = similar = don't cut)
  • t-links (terminal): Edges to S (foreground probability) and T (background probability)
E(f) = ∑ Dp(fp) + λ · ∑ Vpq(fp, fq) [Data term + Smoothness term]
Build graph: pixels as nodes, similarity as edge weights
User marks foreground seeds (→ Source) and background seeds (→ Sink)
Assign t-link weights using color/intensity histograms (GMM)
Run max-flow / min-cut algorithm (Ford-Fulkerson)
Min-cut partition = segmentation boundary
S (Source/Foreground) | | |t-link |t-link | | [p1]─n─[p2]─n─[p3] ← pixels (nodes) | | |t-link |t-link | | T (Sink/Background) Min-cut: find minimum weight set of edges to cut → separates Foreground from Background
✅ Pros
  • Global optimal solution
  • No leakage across weak edges
  • User seeds refine result
  • Handles intensity inhomogeneities
❌ Cons
  • Slow for large 3D volumes
  • Graph construction memory intensive
  • Requires seed points
⚠ Hybrid Pipeline (Exam Answer for Q5,Q6)Region Growing (coarse) → Active Contour (boundary refinement) → Graph-Cut (global optimization). Each stage: RG gives initial mask, AC aligns to edges, GC minimizes leakage globally.
Clustering

Mean-Shift Segmentation

Definition Non-parametric density estimator. Pixels are iteratively shifted toward regions of higher density in feature space (color + spatial) until convergence. Pixels converging to same mode = same segment.
m(x) = [∑ K((x−xi)/h)·xi] / [∑ K((x−xi)/h)]    x ← m(x)
Represent each pixel as feature vector (L,a,b color + x,y position = 5D)
For each pixel, compute mean of nearby pixels within bandwidth h
Shift pixel toward computed mean
Repeat until shift < ε (pixel converged to density peak = mode)
Pixels sharing same mode → same segment
✅ Pros
  • No need to specify #clusters
  • Finds arbitrarily shaped regions
  • Robust to outliers
❌ Cons
  • Bandwidth h is sensitive — hard to tune
  • Very slow O(n²) per iteration
  • Over-segments complex textures
Probabilistic

Markov Random Fields (MRF)

Definition MRF is a probabilistic graphical model where each pixel's label depends only on its neighbors (Markov property). Used for image restoration, texture classification, segmentation.

Energy Formulation

E(f) = ∑ψ_i(fi) + ∑ψ_ij(fi,fj) [Unary + Pairwise potentials]
  • Unary potential ψ_i: Cost of assigning label f to pixel i (from observed intensity)
  • Pairwise potential ψ_ij: Cost of adjacent pixels having different labels (encourages smoothness)
  • MAP-MRF: Find labeling f that minimizes E(f)
  • Solved by: Belief Propagation, Graph-Cut (for submodular energies)
✅ Pros
  • Principled probabilistic framework
  • Incorporates spatial context
  • Can model complex label interactions
❌ Cons
  • Complex to design & optimize
  • Slow inference
  • Requires parameter tuning
Texture

Texture Segmentation

Definition Segments regions based on texture properties (regular patterns, roughness, directionality) rather than just intensity.

Methods

  • Gabor Filters: Sinusoid multiplied by Gaussian. Detects specific frequencies and orientations. Bank of filters → texture feature vector per pixel.
  • LBP (Local Binary Patterns): Encode local texture by thresholding neighbors relative to center pixel → histogram.
  • Co-occurrence Matrix (GLCM): Statistical measure of how often pairs of pixel values co-occur.
  • DWT (Discrete Wavelet Transform): Multi-resolution decomposition → energy at each sub-band = texture feature.
Gabor Filter Bank: θ=0° θ=45° θ=90° θ=135° ║║║║ ╲╲╲╲ ═══ ╱╱╱╱ Each filter detects edges at specific orientation+frequency → Response vectors → Cluster → Segment by texture class

Pattern Analysis — Clustering, Classification, Dimensionality Reduction

⚠ EXAM HOT

K-Means Clustering

Definition Partitions n data points into k clusters by iteratively assigning points to the nearest centroid and recomputing centroids.
Objective: minimize J = ∑ᵢ ∑ₓ∈Cᵢ ||x − μᵢ||²
Initialize: randomly choose k centroids μ₁,...,μₖ
Assignment: assign each point x to cluster with nearest centroid: c(x) = argmin_i ||x − μᵢ||²
Update: recompute centroid as mean of assigned points: μᵢ = (1/|Cᵢ|) · ∑ x∈Cᵢ x
Repeat steps 2-3 until assignments don't change (convergence)
🔢 Numerical Example (Image Segmentation with Q3 from Mock)

Given 4×4 matrix I, apply K-Means with k=3:

Data points: [15,20,10,25, 120,115,125,110, 130,140,135,145, 240,235,245,250] k=3, initial centroids: μ₁=15 (dark), μ₂=125 (mid), μ₃=240 (bright) Iteration 1 Assignment: 15,20,10,25 → μ₁ (cluster 1, dark) 120,115,125,110,130,140,135,145 → μ₂ (cluster 2, mid) 240,235,245,250 → μ₃ (cluster 3, bright) Update centroids: μ₁ = (15+20+10+25)/4 = 17.5 μ₂ = (120+115+125+110+130+140+135+145)/8 = 127.5 μ₃ = (240+235+245+250)/4 = 242.5 Converged! → 3 segments: dark, mid-tone, bright
✅ Pros
  • Simple and fast O(nkt)
  • Scales to large data
❌ Cons
  • Must specify k in advance
  • Sensitive to initialization
  • Assumes spherical clusters
  • Affected by outliers

Probabilistic

Gaussian Mixture Models (GMM)

Definition Models data as a mixture of K Gaussian distributions. Each component has its own mean (μ), covariance (Σ), and mixing weight (π). More flexible than K-Means.
p(x) = ∑ᵢ πᵢ · N(x | μᵢ, Σᵢ)    where ∑πᵢ = 1

EM Algorithm (Expectation-Maximization)

E-step: Compute responsibility r_ik = P(cluster k | point xᵢ) for each point
M-step: Update μ, Σ, π using weighted averages
Repeat until log-likelihood converges
✅ Pros
  • Soft assignments (probabilistic)
  • Handles elliptical clusters
  • Returns cluster probabilities
❌ Cons
  • Must specify k
  • Can converge to local optima
  • Slower than K-Means

Naive Bayes Classifier

P(C|x) = P(x|C) · P(C) / P(x)    [Posterior = Likelihood × Prior / Evidence]
  • Assumes features are independent (naive assumption)
  • Fast, works well with small datasets
  • Good when features are actually independent (text classification)

K-Nearest Neighbors (KNN)

Compute distance from query point to all training points
Find K nearest neighbors
Assign majority class label among the K neighbors
dist(x,xi) = √∑(xⱼ − xiⱼ)²    [Euclidean distance]
  • No training phase (lazy learner)
  • K=1 → noisy; K=large → smooth but misclassifies boundary
  • Curse of dimensionality: performance drops in high dimensions

Artificial Neural Network (ANN)

Forward pass: input → hidden layers → output (softmax/sigmoid)
Compute loss (cross-entropy)
Backpropagation: compute gradients using chain rule
Update weights: w ← w − η·∂L/∂w

Discriminant Function

g(x) = wᵀx + w₀    [Linear discriminant]
  • Divides feature space into decision regions
  • If g(x) > 0 → Class 1; if g(x) < 0 → Class 2
  • Linear discriminant: straight line boundary
  • Quadratic discriminant: curved boundary (when covariances differ)
  • Outliers: pull decision boundary → use robust estimators or K-Medoids
⚠ EXAM HOT

Dimensionality Reduction — PCA, LDA, ICA

PCA — Principal Component Analysis

Definition Unsupervised linear method. Projects data onto directions of maximum variance (principal components). No class labels needed.
Center data: x̃ = x − μ (subtract mean)
Compute covariance matrix: C = (1/n)·X̃ᵀX̃
Compute eigenvalues λᵢ and eigenvectors vᵢ of C
Sort by eigenvalue (descending), select top k eigenvectors
Project: y = Wᵀx̃ where W = [v₁|v₂|...|vk]

LDA — Linear Discriminant Analysis

Definition Supervised linear method. Maximizes class separability: maximize ratio of between-class to within-class scatter.
J(W) = (Wᵀ SB W) / (Wᵀ SW W)    [Between-class / Within-class scatter]
  • Requires class labels → supervised
  • Max (c−1) discriminant dimensions for c classes
  • Better for classification than PCA

ICA — Independent Component Analysis

Definition Finds statistically INDEPENDENT components (not just uncorrelated like PCA). Used for blind source separation (e.g., separating mixed audio, EEG signals).
x = A·s    ICA finds: W such that y = Wx has independent components

UNIT 04

Motion Analysis — Background Subtraction, Optical Flow, KLT

⚠ KEY TOPIC

Background Subtraction & Modeling

Definition Separates moving foreground objects from static background by comparing current frame to a background model.

Simple Frame Difference

D(x,y,t) = |I(x,y,t) − I(x,y,t−1)|    Foreground if D > threshold
  • Fast but misses slow objects, creates double contours

Background Modeling Methods

  • Running Average: B(t) = α·I(t) + (1−α)·B(t−1). Simple, adapts slowly. α controls adaptation rate.
  • MOG (Mixture of Gaussians): Model each pixel as GMM. Multiple background modes (waving trees, flicker). Handles multimodal backgrounds. Best for outdoor surveillance.
  • MOG2: Adaptive MOG — auto-selects number of components. OpenCV default.
t=1: bg model B₁ │ t=2: new frame I₂ │ ▼ |I₂(x,y) - B₁(x,y)| > T ? ├── YES → Foreground (moving object) └── NO → Background → Update B B(t) ← α·I(t) + (1-α)·B(t-1)
✅ Pros
  • Fast and simple
  • MOG handles dynamic backgrounds
❌ Cons
  • Fails with sudden illumination change
  • Shadow effects
  • Needs fixed camera
⚠ EXAM HOT

Optical Flow

Definition Apparent motion of image pixels between consecutive frames. Gives a 2D velocity field (u,v) per pixel or feature point.

Optical Flow Constraint Equation

∂I/∂x · u + ∂I/∂y · v + ∂I/∂t = 0    →    Ix·u + Iy·v = −It
  • Ix, Iy = spatial gradients; It = temporal gradient
  • 2 unknowns (u,v), 1 equation → underdetermined (aperture problem)

Lucas-Kanade (Sparse / Feature-based)

  • Assumes motion is constant within a small local window
  • Solves: [u;v] = (AᵀA)⁻¹ Aᵀ b where A = [Ix, Iy] for each pixel in window
  • Works well for sparse feature points (corners)

Horn-Schunck (Dense)

  • Adds global smoothness constraint: minimize ||∇u||² + ||∇v||²
  • Computes flow at EVERY pixel (dense field)
Frame t Frame t+1 ┌─────────────────────────────┐ │ ●──────────────►● │ │ obj@(x,y) obj@(x+u, y+v) └─────────────────────────────┘ Optical Flow vector: (u, v) per feature point u = horizontal velocity v = vertical velocity
✅ Pros
  • Estimates per-pixel motion
  • Works for moving camera
  • No explicit segmentation needed
❌ Cons
  • Fails with large motion
  • Aperture problem
  • Dense OF is slow
⚠ Exam TipBackground Subtraction = WHAT moved (binary foreground mask). Optical Flow = HOW it moved (velocity vectors). Use both together: BS detects movers, OF estimates direction and speed.
Feature Tracker

KLT Tracker (Kanade-Lucas-Tomasi)

Definition Feature tracker that selects good features (high gradient regions = corners) and tracks them using Lucas-Kanade optical flow across frames.

Algorithm

Select feature points using Shi-Tomasi criterion: λ_min of structure tensor > threshold
For each feature, compute Lucas-Kanade displacement (u,v) to next frame
Update feature position: x' = x+u, y' = y+v
Check tracking quality: if tracking error > threshold → delete feature
Add new features if too few remain

Shi-Tomasi Feature Quality

Quality(p) = min(λ₁, λ₂) > threshold    [Both eigenvalues large = good corner]
✅ Pros
  • Fast and reliable tracker
  • Works in real-time
  • Handles affine deformations
❌ Cons
  • Fails with large motion
  • Needs good texture (can't track flat regions)
Advanced

Spatio-Temporal Analysis & Dynamic Stereo

Spatio-Temporal Analysis: Extends spatial analysis to the time dimension. Video = 3D volume (x, y, t). 3D features capture both spatial appearance and temporal motion patterns.

Spatio-Temporal Interest Points (STIP)

  • Extend Harris detector to 3D: detect corner-like structures in (x,y,t)
  • Used for action recognition in videos

Dynamic Stereo

  • Stereo matching applied to video sequences over time
  • Use both spatial stereo disparity AND temporal flow constraints
  • Better depth estimation for moving objects

Motion Parameter Estimation

  • Translational motion: Uniform (u,v) across frame — global motion
  • Affine motion: 6-parameter model: u = a₁+a₂x+a₃y, v = a₄+a₅x+a₆y
  • Homography: 8-parameter projective model for planar scenes

Standard Answer Templates for Common Question Types

Template: Feature Extraction Pipeline (Q in warehouse/robot etc.)

Edge Detector (Canny) → detect all edges → input to Hough
Hough Transform → detect straight lines (shelves, walls)
Corner Detector (Harris) → find shelf corners, anchor points
Descriptor (SIFT/HOG) → identify/classify objects on shelves

Template: Segmentation Hybrid Pipeline

Noise removal: Gaussian blur or median filter
User provides seeds → Region Growing (coarse segmentation)
Active Contour / Level Set → refine boundary to edges
Graph-Cut → global optimization, prevents leakage
Output: clean binary mask ready for downstream detection

Template: Pattern Analysis Pipeline

Extract features from data (intensity, texture, etc.)
Dimensionality Reduction: PCA (unsupervised) or LDA (supervised)
Clustering: K-Means (fast) or GMM (soft) or K-Medoids (robust)
Classification: KNN (simple) or ANN (complex) → discriminant function for decision

Template: Surveillance / Motion Pipeline

Background Subtraction (MOG2) → detect WHAT moved (foreground mask)
Optical Flow (Lucas-Kanade) → detect HOW they moved (velocity vectors)
KLT Tracker → track individual people/objects across frames
Dimensionality reduction (PCA) on features → KNN for person identification
