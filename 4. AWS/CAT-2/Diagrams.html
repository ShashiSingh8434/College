Amazon VPC — Virtual Private Cloud

Core Networking
Amazon VPC lets you provision a logically isolated section of the AWS Cloud where you can launch AWS resources in a virtual network that you define. You have complete control over your virtual networking environment, including selection of your own IP address range, creation of subnets, and configuration of route tables and network gateways.

A VPC spans all Availability Zones in a Region. Subnets are created within a single AZ. Public subnets have a route to an Internet Gateway; Private subnets do not, and rely on a NAT Gateway to reach the internet.
MAJOR DIAGRAM — VPC Architecture: Public & Private Subnets, IGW, NAT Gateway, Route Tables, Security Groups
MINOR DIAGRAM — Security Group vs Network ACL comparison
VPC CIDR
e.g. 10.0.0.0/16 — gives 65,536 IPs. Subnets carve it into smaller blocks.
NAT Gateway
Sits in a public subnet, lets private instances initiate outbound internet traffic while blocking inbound.
Route Table
Each subnet has an associated route table. The local route covers VPC traffic; other routes point to IGW, NAT, peering connections, etc.
Security Groups
Stateful, applied to instances. Default: deny all inbound, allow all outbound. Rules added explicitly.

Amazon Route 53

DNS & Routing
Amazon Route 53 is a highly available, scalable cloud DNS (Domain Name System) web service. It routes end users to internet applications by translating human-readable domain names into IP addresses. Route 53 also offers domain registration and health checking.
MAJOR DIAGRAM — Route 53 Routing Policies Flow
Hosted Zone
Container for DNS records for a domain. Public hosted zones route internet traffic; private ones route within VPC.
Record Types
A (IPv4), AAAA (IPv6), CNAME (alias), MX (mail), TXT (verification), NS (name server).
TTL
Time-To-Live — how long a DNS resolver caches the response before querying again.
Alias Record
Route 53 specific — maps to AWS resources (ELB, CloudFront) without needing an IP address.

Amazon API Gateway

API Management
Amazon API Gateway is a fully managed service that makes it easy to create, publish, maintain, monitor, and secure APIs at any scale. It acts as the front door for applications to access backend services such as Lambda, EC2, or any public web service. Supports REST APIs, HTTP APIs, and WebSocket APIs.

AWS Identity and Access Management (IAM)

Security & Identity
AWS IAM enables you to manage access to AWS services and resources securely. IAM is free and global (not region-specific). The default behavior is deny all — you must explicitly grant permissions. IAM has four core components: Users, Groups, Roles, and Policies.
MAJOR DIAGRAM — IAM Components and their relationships
Least Privilege
Grant only the minimum permissions needed. Start with zero and add as required.
Best Practices
Avoid using root user daily. Use MFA. Rotate access keys. Use Roles over Users for services.
ARN
Amazon Resource Name uniquely identifies every AWS resource. Format: arn:aws:service:region:account-id:resource
STS
Security Token Service issues temporary credentials when a Role is assumed. Credentials expire automatically.

AWS Certificate Manager (ACM) & Key Management Service (KMS)

Encryption
ACM lets you provision, manage, and deploy SSL/TLS certificates for use with AWS services (ELB, CloudFront, API Gateway). Certificates can be issued free of charge for public domains and auto-renew.

AWS KMS makes it easy to create and control cryptographic keys used to encrypt your data. It integrates with most AWS services. Keys can be AWS-managed, Customer-managed (CMK), or imported.

Amazon RDS — Relational Database Service

Managed Database
Amazon RDS makes it easy to set up, operate, and scale a relational database in the cloud. It automates time-consuming tasks such as backups, software patching, automatic failure detection, and recovery. Supported engines: MySQL, PostgreSQL, MariaDB, Oracle, Microsoft SQL Server, Aurora.
MAJOR DIAGRAM — RDS Multi-AZ vs Read Replicas
Automated Backups
Enabled by default. Retention up to 35 days. Point-in-time recovery (PITR) supported.
RDS Snapshots
Manual DB snapshots, can be shared/copied cross-region, retained even after instance deletion.
Instance Classes
General Purpose (M series), Memory Optimised (R series), Burstable (T series).
Storage
Backed by EBS — gp2, gp3 (SSD) or io1 (Provisioned IOPS). Auto-scale storage supported.
📋 Steps to Create an Amazon RDS Instance
From AWS Console:
1. Go to RDS → Create database.
2. Choose Standard Create and select engine (MySQL, PostgreSQL, etc.).
3. Pick a template: Production (Multi-AZ enabled) or Free tier.
4. Set DB instance identifier, master username and password.
5. Choose instance class (e.g. db.t3.micro for free tier).
6. Configure storage type (gp2/gp3) and allocated storage.
7. Set VPC, subnet group, and Security Group (allow port 3306 for MySQL).
8. Enable Multi-AZ if production. Enable automated backups and set retention.
9. Click Create database. Endpoint available once status is Available.

Amazon DynamoDB

NoSQL Database
Amazon DynamoDB is a fully managed, serverless, key-value and document NoSQL database with single-digit millisecond performance at any scale. No infrastructure to manage. Tables scale automatically with on-demand or provisioned capacity modes.
MAJOR DIAGRAM — DynamoDB Data Model: Tables, Items, Attributes, Keys, GSI
Serverless
No servers to manage. Scales to zero, scales to petabytes. Pay only for what you use.
DynamoDB Streams
Ordered stream of item-level changes. Used to trigger Lambda on inserts/updates/deletes.
DAX
DynamoDB Accelerator — in-memory cache, reduces read latency from ms to microseconds.
Global Tables
Multi-region, multi-master replication for globally distributed apps.
📋 Steps to Create a DynamoDB Table
1. Go to DynamoDB → Create table.
2. Enter Table name (e.g. Users) and Partition key (e.g. userId — String).
3. Optionally add a Sort key (e.g. createdAt — String).
4. Choose Table settings: Default settings (On-Demand) or Custom (Provisioned with RCU/WCU).
5. Optionally create a GSI under Indexes.
6. Configure encryption (default: AWS-owned key) and tags.
7. Click Create table. Explore items via the Explore table items tab.

Amazon Redshift

Data Warehouse
Amazon Redshift is a fully managed, petabyte-scale data warehouse service in the cloud. It uses columnar storage, parallel query execution (MPP — Massively Parallel Processing), and compression to deliver fast query performance on large datasets. Used for analytics and Business Intelligence (BI) workloads.
DIAGRAM — Redshift Architecture: Leader Node + Compute Nodes + Slices
Columnar Storage
Stores data by column, not row. Enables high compression and fast aggregation queries.
COPY Command
Most efficient way to load data into Redshift — loads from S3, DynamoDB, EMR, or remote hosts in parallel.
Redshift vs RDS
RDS = OLTP (many small transactions). Redshift = OLAP (large complex analytical queries on big data).
Redshift Serverless
Automatically provisions and scales data warehouse capacity — pay only for what you use.

Infrastructure as Code & CI/CD

Elastic Load Balancing (ELB) & EC2 Auto Scaling

High Availability
Elastic Load Balancing automatically distributes incoming application traffic across multiple targets (EC2, Lambda, containers) across multiple AZs. Coupled with Auto Scaling Groups, it enables your application to handle varying loads while maintaining availability.
MAJOR DIAGRAM — ALB + Auto Scaling Group: Traffic Distribution
MINOR DIAGRAM — Types of Elastic Load Balancers
Feature Application LB (ALB) Network LB (NLB) Classic LB (CLB)
OSI Layer Layer 7 (HTTP/HTTPS) Layer 4 (TCP/UDP/TLS) Layer 4/7
Routing Path, Host, Header, Query IP and Port Round-robin
Performance High Ultra-high, millions req/s Legacy
Use Case Web apps, microservices Gaming, IoT, real-time Legacy apps
WebSocket ✅ Supported ✅ Supported ❌
Auto Scaling Policies
Target Tracking (e.g. keep CPU at 50%), Step Scaling, Scheduled Scaling, Predictive Scaling.
Launch Template
Defines AMI, instance type, SG, key pair for new instances in the ASG. Replaces Launch Configuration.
Target Groups
ALB routes traffic to target groups. Health checks run per target. Targets can be EC2, IP, Lambda.
Cooldown Period
Period after a scaling activity where ASG does not launch/terminate more instances (default: 300s).
📋 Steps to Create an Application Load Balancer
1. Go to EC2 → Load Balancers → Create Load Balancer → Application Load Balancer.
2. Name it, set scheme (internet-facing or internal), and IP address type (IPv4).
3. Under Network mapping: select VPC and at least 2 subnets across different AZs.
4. Assign a Security Group (allow HTTP:80, HTTPS:443 inbound).
5. Configure Listeners: HTTP:80 and/or HTTPS:443 (attach ACM certificate).
6. Create a Target Group: specify type (Instances), protocol (HTTP:80), and health check path (/).
7. Register your EC2 instances in the Target Group.
8. Review and Create load balancer. Use the DNS name to test traffic distribution.

CloudWatch & CloudTrail

Monitoring & Governance
Amazon CloudWatch is a monitoring and observability service. It collects metrics, logs, and events from AWS resources and applications. You can set Alarms that trigger actions (Auto Scaling, SNS notifications) when thresholds are breached.

AWS CloudTrail records API calls made in your AWS account — who did what, when, from where. Used for auditing, compliance, and security analysis. CloudTrail logs every management action (console, SDK, CLI, API).
MAJOR DIAGRAM — CloudWatch: Metrics, Logs, Alarms, Events Pipeline
DIAGRAM — CloudTrail: API Audit Trail Flow
CloudWatch Metrics
Pre-built metrics: CPU, NetworkIn/Out, DiskRead/Write, StatusCheckFailed. Custom metrics: your own app data.
Log Groups
Container for log streams from EC2 (via CloudWatch Agent), Lambda, API Gateway, and other services.
CloudTrail Trail
A trail delivers event logs continuously to S3. Use multi-region trails + log file integrity to ensure complete audit coverage.
CloudTrail vs CloudWatch
CloudTrail = who did what (API history, governance). CloudWatch = what is happening now (performance, metrics, alarms).
