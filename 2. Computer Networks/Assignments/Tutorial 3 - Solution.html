Question 1

Application creates a 200-byte message. Each layer (5 layers total, including the fifth and the first) adds a 10-byte header. Find the efficiency of the system.

Step 1: Identify data and overhead
Application layer data = 200 bytes
Number of layers = 5 (Application, Transport, Network, Data Link, Physical)
Header added by each layer = 10 bytes
Step 2: Total header overhead
Total overhead = 5 × 10 bytes = 50 bytes
Step 3: Total bytes transmitted
Total transmitted = Data + Overhead = 200 + 50 = 250 bytes
Step 4: Efficiency
Efficiency = (Application bytes / Total bytes transmitted) × 100 = (200 / 250) × 100
Efficiency = 80%
Question 2

A CSMA/CD network has bandwidth 5 Mbps and maximum propagation time (Tp) = 25.6 µs (ignore jamming signal time). Calculate the minimum frame size.

Step 1: Recall the CSMA/CD constraint
For collision detection to work, transmission time must be at least twice the propagation time:
Tfr ≥ 2 × Tp
Step 2: Compute minimum transmission time
Tfr = 2 × 25.6 µs = 51.2 µs
Step 3: Compute minimum frame size
Frame size = Bandwidth × Tfr = 5 × 106 bps × 51.2 × 10-6 s
Minimum frame size = 256 bits (32 bytes)

Question 8

During an online exam, thousands of students access the server simultaneously, overloading routers. Explain congestion control using: Backpressure, Choke Packet, Implicit Signaling, Explicit Signaling.

(i) Backpressure
Detection: A congested router notices its buffers filling up (it cannot forward packets as fast as they arrive).
Action: It refuses to accept further packets from the immediately upstream node, or asks it to slow down. That upstream node in turn slows down or refuses packets from its own upstream neighbour, and the effect propagates hop-by-hop, all the way back toward the source (the exam servers/students), until the sending rate is throttled. This works only in networks with virtual-circuit / hop-by-hop flow control (e.g., X.25), not natively in datagram networks like the Internet.
(ii) Choke Packet
Detection: A congested router directly detects buffer overflow or rising queue length.
Action: Instead of notifying only the previous hop, the congested router sends a special "choke packet" directly to the source host (e.g., the exam server), bypassing intermediate nodes. On receiving it, the source reduces its sending rate by a fixed percentage. The source ignores further choke packets for a fixed time interval to allow the reduction to take effect, then again listens for new choke packets.
(iii) Implicit Signaling
Detection: There is no explicit congestion message from the network. Instead, the source infers congestion indirectly — for example, by observing increased round-trip delay, packet loss, or retransmission timeouts (as TCP does).
Action: On detecting these implicit signs, the source (student's machine / server) assumes the network is congested and voluntarily reduces its transmission window/rate (e.g., TCP's slow start and congestion-avoidance mechanisms after a timeout).
(iv) Explicit Signaling
Detection: The congested router itself detects the buildup of its queue.
Action: The router explicitly marks or sends a notification bit within the data packets themselves — either forward to the destination (Forward Explicit Congestion Notification, FECN) or backward to the source (Backward Explicit Congestion Notification, BECN). The receiving end system then explicitly signals the sender to reduce the rate. This is used in Frame Relay and in the ECN field of IP/TCP headers on the modern Internet.
Question 9

University network with 500 students uses Leaky Bucket. Bucket capacity = 10 packets, output rate = 2 packets/second. 8 packets arrive at t=0, then 6 more packets arrive at t=1s.

(a) How the Leaky Bucket algorithm handles this traffic
The bucket accepts incoming (bursty) packets up to its capacity of 10. Regardless of how fast packets arrive, they are released ("leaked") onto the network at a fixed, constant rate of 2 packets/second, smoothing out the burst into a steady stream. Any packet that arrives when the bucket is already full is dropped.

(d) How Leaky Bucket improves QoS
It converts an unpredictable, bursty arrival pattern into a smooth, constant-rate output stream. This prevents sudden traffic spikes from overwhelming downstream routers/links, reduces jitter and congestion, and enforces a predictable, fair average bandwidth usage per host — directly improving QoS for all 500 students sharing the network, though at the cost of dropping packets during sustained bursts since it does not allow flexibility above the set rate.
Question 10

Link State Algorithm on the given 5-router topology (A,B,C,D,E).

(a) How router A obtains topology information
Each router (including A) creates a Link State Packet (LSP) listing its ID, its directly connected neighbours, and the cost (link weight) to each. Every router floods its LSP to all other routers in the network (reliable flooding, using sequence numbers to avoid loops/duplicates). Because every router floods its own LSP, router A eventually receives an LSP from every other router (B, C, D, E) and thus learns the complete topology of the network, not just its own local links.
